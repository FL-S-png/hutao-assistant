## 2. 三层崩溃根因（最硬的知识，勿忘）

机器有 4 显示器，其中 3 个是坏虚拟显示器（GameViewer / MuMu / 微软基本显示，Status=Error），GPU 损坏导致：

1. **崩溃 0x80000003 @0x33ef8f1**（Chromium int3，main.js 执行前）→ 独立 GPU 进程共享 context 虚拟化失败 `kFatalFailure: Failed to create shared context for virtualization`
   → **解药：`--in-process-gpu`**（GPU 并入主进程）。
2. **白屏** → 坏 GPU 合成失败 → **`--disable-gpu-compositing`**。
3. **远程网页黑屏 / 登录白屏**（webview partition=persist:bili 独立 renderer `Renderer process launch-failed`）
   → **`--no-sandbox`**（坏 GPU 所致，非弹窗拦截）。

**三处快捷方式（Public 桌面 + 开始菜单 2 处）统一 Args**：
`--in-process-gpu --disable-gpu-compositing --no-sandbox`

**注意 `--disable-gpu-compositing` 只禁合成器，不禁视频硬解（DXVA）；坏 GPU 环境 Chromium 降级 SwiftShader，故 `--in-process-gpu` 必需。**

## 12. 去启动器登录按钮 + 分 P 液态玻璃 + 双向联动（2026-11-17 00:38）

- **去掉「登录账号」按钮**：`src/console/index.html` 里 `.card-head` 的 `<button id="btnLogin">` 整块删除，`console.js` 的 `wireSettings()` 里对应 click 处理一并移除。理由：复制链接跟跑时浮窗顶部自己会弹 B 站登录条，在那儿登录即可，启动器多一个入口纯属重复。
- **分 P 换皮成液态玻璃**：原生 `<select>` 的展开层是系统画的（白底方块），玻璃贴不上去。所以 `#part` 降级成**数据源**（`#part.sel-src` 绝对定位 + 0×0 + `opacity:0` + `pointer-events:none`，用 id 特异性压过 `.sel` 的 `height:36px/padding`），用户真正点的是 `#partBtnG` + `#partMenuG`。
  - `wireGlassPart()`：MutationObserver 监听 `#part` 的选项变化 → 镜像成玻璃菜单项；点菜单项写回 `select.selectedIndex` 并**手工补发 `change`**（代码赋值不触发原生 change），原有「切 P 就重载浮窗」的链路一行不改照常跑。
  - 玻璃观感靠**三层背景 + 高光/内描边兜底**，不是只靠 `backdrop-filter` —— 本机坏 GPU 下 blur 会退化。
  - 菜单项排版和浮窗的分 P 菜单统一：左 `P5/24`（`.dd-num`），右分 P 标题（`.dd-name` 单行省略）。
- **双向联动（本轮重点）**：
  - 旧问题：`#part` 的 change 处理里有 `if (!state.video) return;`，而 `state.video` 只有「本次会话从启动器点过启动跟跑」才有值。视频是浮窗自己续播/热键切的，启动器下拉就是**灰的**，所以「启动器切 P、播放器跟着切」永远不可能。
  - 修法 1（冷启动补数据）：`hydrateLastVideo(s)` —— 开机就拿 `lastText/lastPart` 调一次 `bili:load` 把 `pages` 拉回来，下拉一进来即可用（失败静默，保持占位）。
  - 修法 2（启动器 → 浮窗）：change 改走 `switchPart(p)`，文本回退顺序 `state.video.text → 输入框 → settings.lastText`，缺 `state.video` 时就地补一次 `bili:load` 再 `save(lastPart)` + `load` + **`action('float-load')`**。
  - 修法 3（浮窗 → 启动器）：浮窗 `loadVideo()` 成功后 `action('part-sync', {text,id,title,p,pages})` → 主进程 `case 'part-sync'` 转 `sendTo(consoleWin,'part:sync')` → 启动器 `applyPartSync()` 更新下拉与 `videoMeta`（同 P 直接 no-op，不会来回打乒乓）。preload 新增 `onPartSync`。
- **实测（CDP，新 asar `31bede66…` 544,675B）**：冷启动 `#part` 就有 24 项且 enabled；玻璃菜单点 P3 → 浮窗 `state.p=3`、标题变「晶树溶洞(1)」；浮窗 `loadVideo(id,5)` → 启动器下拉自动变 `P5/24`、`videoMeta` 变「当前 P5/24」。双向均通。
- **asar 归档**：`2f2e3670…`（玻璃分P初版）→ `31bede66…`（联动版，当前部署）。旧包备份在 `C:\tmp\asar_backup\portable_1117-003104_pre-glasspart.bak` 与 `portable_1117-0037xx_pre-partsync.bak`。源码权威目录：`C:\tmp\grb_true`。

## 13. 便携版「一键建桌面图标」脚本（2026-11-17 00:42）

- **起因**：§11 那个桌面 lnk 是手工补救的副产物，换机器/重解压/换版本都不会自动出现；用户要「解压后自动建图标」。
- **交付物**（都在便携版目录 `C:\Users\Administrator\Desktop\胡桃助手-便携版\胡桃助手\`）：
  - `create 入口` → `创建桌面快捷方式.cmd`（137B，内容全 ASCII；双击运行，带 `-Quiet` 等参数时不再 pause）

- **脚本逻辑**：
  1. 用 `$PSScriptRoot` 定位同目录 exe（兜底：往下两级找名字带 胡桃/genshin/route 的 exe；排除 unins/elevate/crashpad/update，限 >1MB）。
  2. `Get-CimInstance Win32_VideoController` 逐个打印 Name/Status/ConfigManagerErrorCode；判定"异常"的三个条件：`Status -ne 'OK'`、`ConfigManagerErrorCode -ne 0`、名字匹配 `基本显示|Basic Display`。**有异常 → 追加三参；全部正常 → 裸启动**（好显卡机器不白降性能）。查不到 WMI → 保守带参。
